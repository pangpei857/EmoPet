## 4. 当前已实现的产品能力

### 4.1 桌宠与专注计时

透明悬浮、眼睛跟随鼠标、头/肚子/尾巴分区互动、拖动吸附、70%—160%缩放、置顶、位置锁定、找回、托盘、可关闭气泡与四类动作均保留。隐藏后不会被普通提醒自动唤回；长气泡折行、悬停暂停消失，布局变化保持脚下锚点。

学习任务支持15/25/45分钟及自定义1—120分钟、开始/暂停/继续/结束、5分钟休息和到点反馈；单调时间计算避免tick丢失导致计时漂移。关闭学习面板不停止计时，完成记账幂等。

现有动作仍以原画遮罩、分层变换和绘制效果为主，没有完整走路/坐下序列帧。原始图在 `assets/raincoat-reference.png`，来源说明在 `assets/visual-source.md`。

### 4.2 视觉陪伴

入口：学习面板的“视觉陪伴”，或右键/托盘的“视觉陪伴 · 摄像头”。

已支持设备枚举、刷新、选择、启停、镜像、手机框/脸框/手部点、眉部数值、推理耗时、失败提示和超时恢复。采集/推理在spawn子进程，有界队列优先最新帧；关闭视觉窗口会停止采集、清空预览并释放设备，应用退出关闭子进程。

本地视频测试用于无摄像头时验证模型，**只显示检测结果，不触发自动提醒，也不进行个人校准**。采集目标参数并非实测帧率保证。

| 策略 | 当前代码默认值/行为 |
| --- | --- |
| 手机判断 | YOLOv8s ONNX检测COCO类别67；手机附近至少3个手部关键点，才是关系线索 |
| 手机提醒 | 线索持续12秒，默认仅专注RUNNING且未到时、恰有一张脸、桌宠可见时触发 |
| 眉部关怀 | `browDownLeft/Right`均值持续5秒，基础阈值0.45 |
| 个人基线 | 单人自然表情至少3秒、至少8样本取中位数；实际阈值至少为基线＋0.18，上限0.95 |
| 冷却 | 手机与关怀共用120秒冷却；同次判断手机优先 |
| 证据重置 | 无人/多人、时间倒退、帧间隔超过2秒、隐藏、暂停提醒、默认非专注状态会重置；短暂阴性时间不加入正证据 |
| 暂停设置 | 手机/关怀开关、持续时间、阈值、冷却可保存；暂停全部提醒10分钟 |

策略是待实测的启发式规则。`eyes_down`虽有提取，但未参与决策，不等于已实现头部姿态或精确视线估计。低光、遮挡、侧脸、小目标等质量处理仍有限，真实泛化效果未知。

### 4.3 提醒回应与逐轮学习记录

- “我在查资料”：手机提醒暂停5分钟，眉部关怀保留；本轮结束或新一轮开始会恢复该轮的手机抑制。
- “这次识别错了”：保存误报标签，同类提醒暂停1分钟；不自动改阈值或重训模型。
- “稍后提醒”：暂停全部视觉提醒10分钟，可提前恢复。
- 无摄像头可从菜单或记录页发送示例提醒。示例明确标识，不开启摄像头、不污染真实统计、不改变真实策略状态。
- 记录任务、计划时长、实际投入、起止时间、暂停次数、完成状态、关联提醒与回应。旧轮次可补标误报，但不能抑制新轮次。
- 支持今天/近7天/全部；休息单独记录，暂停时间排除，跨午夜按日期分摊。
- 约10秒自动检查点，关键状态变更立即保存；异常退出后仅保留最近一次保存并标记“意外中断”。原版当日汇总迁移一次，不伪造原本不存在的明细。

### 4.4 DeepSeek对话与任务拆解

入口：学习面板“学习对话”，或右键“和皮卡丘聊聊 · DeepSeek”。

已支持：服务地址/模型/Key配置及连接测试、流式显示、停止生成、部分回复保留、本地历史、新建对话、可选当前任务上下文、任务JSON拆解、步骤编辑和保存。Ctrl+Enter发送，Enter换行。聊天窗口关闭会停止本地请求，不自动重试收费请求。

选中的步骤只填入学习面板，由用户点击开始；进行中/暂停的轮次不得覆盖。聊天完整回答在面板显示，桌宠气泡显示摘要。

当前代码默认服务为 `https://api.deepseek.com`、默认模型 `deepseek-flash`，配置下拉还含 `deepseek-v4-pro`，模型名可编辑。**这些是导出时源码配置值，本次未重新验证服务端可用模型。** 真实请求前按当时官方文档和账户权限核对，不能因为本地兼容接口通过就认为账户可用。

聊天上下文仅取已完成轮次，最多8轮、约24000字符；单次输入最多6000字符，回复上限48000字符。仅使用最终文字，内部思考不显示、不保存。拆解提示期望3—6步，校验器允许1—8步，每步名称1—80字、时长1—120整数分钟。

## 7. 下一位 Agent 的任务顺序与验收标准

### 优先一：完成真实DeepSeek账户验收

由用户在应用的“模型配置”输入自己的Key，不在聊天或交接文件里传递。先核对当前服务实际支持的模型名/请求字段，再完成：连接测试、普通中文学习问答、流式停止、关闭重开历史、任务拆解、编辑步骤、放入面板及开始计时。

**验收：**真实返回结果而非fixture；上下文勾选确实生效；进行中轮次不被覆盖；停止保留部分且不会自动重复请求；密钥未进入普通设置/数据库/日志。记录真实服务版本、模型和结果，禁止将本地接口测试包装成真实调用。若暂无Key，可先整理步骤和兼容性检查，不绕过凭据直接调用。

### 优先二：在用户笔记本完成真实摄像头试用

先跑完整模型检查，再确认取景能同时覆盖脸、手与手机，做自然表情校准。至少30分钟真实学习试用，覆盖看屏幕、看书、写字、喝水、手机静置、拿手机查资料、持续持机、短暂/持续皱眉、低头/侧脸、离座、多人和较暗光线。记录系统提醒与用户判断，再调整参数。

**验收：**设备可反复开启关闭并释放；无人/多人/隐藏/休息/暂停学习时符合当前开关行为；“查资料”只暂停手机、误报只抑制同类、示例不污染真实状态；记录平均/高分位推理耗时、CPU/内存、漏检条件和误提醒次数。不要为了演示成功仅降低阈值而省略反例。

### 优先三：依据证据修复和完成交付整理

## 8. 可直接使用的开发命令

以下在项目根目录运行；从 `source_snapshot` 接手时先在该目录建立自己的 `.venv`。已有导出模型，无需重新训练或下载。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt

# 独立测试profile；不触碰日常设置和学习数据
.\.venv\Scripts\python.exe main.py --profile-dir .artifacts/handoff-qa-profile
# 也可附加 --open-chat 直接打开聊天窗口

# 当前76项回归及4组冒烟；聊天使用本地模拟服务
$env:QT_QPA_PLATFORM = 'offscreen'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe main.py --smoke-test
.\.venv\Scripts\python.exe main.py --companion-smoke-test
.\.venv\Scripts\python.exe main.py --chat-smoke-test
.\.venv\Scripts\python.exe main.py --vision-smoke-test --vision-fixtures ..\verification\fixtures
Remove-Item Env:QT_QPA_PLATFORM

# 可加 --preview-path .artifacts/preview.png 保存预览
# 默认构建写入dist：先保留发布版，完成候选验证再替换
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

上面的 `..\verification\fixtures` 按“在本包source_snapshot内运行”书写；实时项目可改用 `.artifacts/vision-fixtures`。公开样例也可由 `tools/fetch_vision_fixtures.py` 重新取得。

## 9. 包内容与交接方式

- `项目进度与Agent交接报告.md`：主报告。
- `给接手Agent的启动指令.md`：可直接粘贴到下一位Agent的任务提示。
- `source_snapshot/`：55个源码、测试、配置、原画、模型、许可、README和计划书文件，包括未提交的最新模块。
- `snapshot_manifest.json`：快照时间及源码文件SHA-256；`environment_observed.json`：已安装环境；`repository_and_release.json`：Git与exe指纹。
- `verification/`：本次5项检查日志（1套单测＋4组冒烟）、测试预览和JSON、6张公开验证图片及来源哈希；`historical/`为既有打包证据。
- `run_check.py`：本次日志捕获辅助脚本；接受标签与完整命令，在source_snapshot下运行，默认离屏、180秒超时。

不包含`.venv`、模型导出环境、完整`dist`/`build`、`.git`历史、真实用户profile或真实Key。本包用于继续开发；当前成品分发请另取项目中的完整 `dist/Momo`。

与旧报告冲突时，以**本报告的时间边界＋当前实际文件/测试**为准。接手后若原项目已有新改动，应先比较哈希和开发记录再继续，不要用此快照覆盖更新成果。
