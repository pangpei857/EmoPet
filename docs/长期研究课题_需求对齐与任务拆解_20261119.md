**学习陪伴智能体：长期研究课题的需求对齐与任务拆解**

整理日期：2026年11月19日。供与导师讨论，尚不是导师批准的任务书。

依据：导师提供的《学习陪伴智能体_研究文献与资源索引_20261117(1).md》、当前项目《课题计划书.md》、README及关键决策与记录模块。本文解释需求、对照现状并提出收敛建议；没有逐篇核验索引中的论文，也没有开展真实用户效果测试。索引中的精读顺序、资源入口等属于待讨论的研究建议，不视为用户要求本次立即执行的操作。

最核心的判断是：现有十二周计划解决“怎样做出一个能运行、能评估的原型”，导师发来的索引把视野扩展到了“一至两年内，围绕学习支持机制提出问题并获得证据”。两者可以衔接，但不能把完成软件功能当作长期研究已经完成，也不能据此断定导师要求所有方向同时展开。

导师的材料更接近“选题地图和证据要求”，正式任务书还需要补上：研究定位、目标人群、核心问题、成果形式、期限与可用资源。

**建议先拿去对齐的一句话目标**

面向成年人在桌面环境中的一种自主学习活动，研究学习陪伴智能体怎样结合可观察线索、学习目标与用户当前意愿，选择是否介入、何时介入及怎样提供支持，并用真实交互和行为数据检验其适宜性与帮助程度。

其中“成年人、桌面环境、一种学习活动”是为了减少初期变量而提出的默认范围，尚需导师确认。学习活动可以从电脑阅读、在线课程或练习题中选一个，不建议第一轮混合所有活动与人群。

建议第一阶段的核心研究问题是：

> 在自主学习中，把“学习者是否需要支持”和“学习者现在是否愿意接受介入”分开判断，并允许用户协商，能否比现有状态触发规则改善支持的适宜性与任务推进，同时控制打扰？

这只是待核查的选题假设，不是已经证实的研究空白。“愿意接受”也不能只由摄像头推断：用户表达、任务阶段与可观察上下文可以共同提供证据，系统应允许未知、拒绝和纠正。

例如，同样是皱眉：用户可能在认真推理，想继续安静学习；也可能已经卡住，希望拆解下一步；还可能需要帮助，但正在做最后一步，想稍后再聊。因此研究重点从“识别动作后说一句关心的话”，进一步转到“当前究竟适不适合介入，以及用户如何决定支持方式”。

后续可以选择一个方向深化：一是记住过去什么支持在什么情境下被接受、随后发生了什么，以改进下一次决策；二是逐渐减少支持，观察学习者能否保持自主规划、监测和调整。第一阶段不建议同时改变触发机制、记忆、表达形式和支持强度，否则很难解释结果由哪个因素造成。

**实际需要完成的任务与交付物**

| 顺序 | 任务 | 具体工作 | 完成时应拿得出的东西 |
| --- | --- | --- | --- |
| 1 | 确定研究边界 | 选定人群、学习活动、使用场所、支持目标；说明系统观察得到什么、哪些情况无法判断 | 一页研究问题说明；约5个典型成功、拒绝和失败场景 |
| 2 | 核实已有研究与差异 | 先核对最接近的学习陪伴、主动介入和记忆工作，再决定哪些值得复现；索引是入口，关键结论需回到原文 | 相关工作比较表：问题、人群、情境、输入、机制、基线、时长、结果、局限、与本课题的差异 |
| 3 | 定义待检验机制 | 分开定义可观察状态、支持需求、可打扰性与当前意愿；定义不介入、延后、轻量动作、询问或实际帮助 | 方法说明、决策流程、可实现的简单基线及主要评价指标 |
| 4 | 将现有产品改成实验原型 | 固定桌宠与基础界面，补策略切换、候选时机记录、反馈与研究数据导出；测试异常和未知状态 | 可复现运行的原型、版本配置、研究日志规范与导出样例 |
| 5 | 获取场景匹配的数据 | 做需求访谈或小规模观察；分别收集动作事实、是否需要支持、此刻是否方便介入与支持偏好；把科研采集和日常运行分开 | 采集与标注规范、知情同意材料、初步样本和错误案例；不要求一开始发布大型数据集 |
| 6 | 先验证核心机制 | 用独立事件或回放检查基本策略，再做真实用户比较；主要改变一个机制，角色、内容与其他条件尽量一致 | 预先确定的实验方案、数据与分析脚本、适宜性和近端行为结果、失败分析 |
| 7 | 验证持续作用并形成成果 | 若要主张持续学习改善，开展跨会话的真实使用；视主线选择记忆或支持渐退研究，分析新奇效应、缺失与退出 | 多次使用的行为证据、研究报告或论文、系统及实验材料、结论边界 |

第1—6项构成第一阶段的研究闭环。第7项是支撑长期主张的后续工作；如果第一阶段只完成短期研究，就应只主张短期机制与体验结果。一至两年的课题可以分成多个阶段，并不意味着一开始就把所有能力和所有长期结论都做齐。

**现有项目可以复用什么，还缺什么**

下列“已有”指项目文档与关键源码中具备相关工程能力，不代表已验证真实识别率或教育效果。

| 当前能力 | 可复用的价值 | 仍需补的研究工作 |
| --- | --- | --- |
| 桌宠、气泡、任务计时、暂停与休息 | 已有统一交互载体 | 冻结外观和主要体验，避免不同实验条件混入角色差异 |
| 手机关联、眉部、低头、在位等视觉候选，含校准和质量拒判 | 可用作情境线索与规则基线 | 独立实拍评价；不要把动作标签直接当作情绪、分心或支持需求标签 |
| 主动提醒、全局与分类冷却、延后 | 已有基础触发策略 | 冷却不等于可打扰性；需要明确时机判断依据及可比较的替代策略 |
| “查资料”“认真思考”“稍后”“误报”等回应 | 已有用户纠正与部分协商入口 | 区分没需求、不方便、策略不合适、识别错了；不能把拒绝统一解释为系统误判 |
| 本地学习、行为、提醒、对话与小结 | 已有跨会话存储和数据关联基础 | 研究日志还需覆盖候选但未提醒的时机、策略版本、条件和后续结果 |
| 历史记录与近期对话上下文 | 能保存和查看过去 | 当前主动决策主要使用当下线索、计时及短期暂停；尚未形成“历史支持策略—回应—结果”进入新决策的长期机制 |
| 自动测试、合成预览与模型链路检查 | 能发现实现和回归问题 | 不能代替自然学习场景的识别评测与真实用户效果研究 |
| 麦克风与叹气检测尚未实现 | 当前没有可直接复用的音频能力 | 旧计划列为必做，新索引未单独规定是否必须；要明确保留、延期还是更新范围 |

关键定位是：当前系统已经适合继续建设成研究平台，没有必要从零重做桌宠；主要新增工作在问题定义、实验记录、决策机制和真实评价。

**日志和数据应服务于哪个问题**

一条可分析的支持记录至少应能回答：在什么任务和情境中，系统看到了什么；根据哪个版本的策略，在何种候选机会下选择介入、等待或不介入；实际是否展示成功；用户怎样回应；预先定义的后续时间窗内发生了什么。

推荐记录候选时机ID、参与者与会话匿名编号、任务类别、感知质量与缺失、当前目标、触发证据、策略版本、实验条件、所选动作、实际展示时间、拒绝或接受原因、后续行为及结果定义。只有采用随机分配设计时，才需要额外记录分配概率与随机化信息。

要在相同的候选机会定义下比较策略，并对部分未触发时段抽样核查，才能估计候选生成阶段的漏支持。只分析已经显示的提醒，会缺少“选择不提醒”和“根本没生成候选”的证据。用户需求与意愿可通过适量、单独设计的回顾确认获得；过密地弹问卷本身也会干扰学习，应先做试用。

策略效果记忆若进入后续研究，建议记住结构化事实：“什么情境—提供何种支持—用户怎样回应—随后观察到什么—何时发生—证据来源—是否仍适用”。不能只保存“用户容易焦虑”等未经确认的标签，也不能把接受提醒直接标记为支持有效。用户应能纠正或删除记忆。

**应该怎样判断研究是否完成**

| 评价层次 | 可以观察什么 | 不能用来替代它的东西 |
| --- | --- | --- |
| 工程能否运行 | 稳定性、延迟、有效观测覆盖率、权限与失败恢复 | 功能清单、演示视频 |
| 感知是否可信 | 独立样本中的查准率、查全率、跨人和跨会话表现、弃判与失败条件 | 合成测试通过、正常帧占多数时的总体准确率 |
| 介入是否合适 | 误打扰、漏支持、接受与拒绝原因、主观负担；结合候选机会数和使用时间报告 | 单纯提醒次数变少，或仅统计已提醒事件的接受率 |
| 当下是否有帮助 | 返回任务、产生下一步行动、任务推进；按选定活动定义 | 气泡被点了、用户说喜欢角色、对话变长 |
| 持续学习是否改善 | 多次使用中的计划落实、持续参与、监测与反思行为及退出情况 | 一次二十分钟试用、一轮完成率 |
| 自主性是否保持 | 减少或撤除支持后是否还能规划、监测和调整；是否出现对系统过度依赖 | 仍有助手时表现较好 |

第一轮可优先比较“现有状态与冷却规则”和“区分需求、时机并可协商的策略”，固定角色、感知来源和基础内容。按研究问题决定是否增加定时提醒条件，不必一次堆叠全部基线。若未来要分别归因需求判断与协商的效果，再设计对应消融。

正式样本量、研究持续时间与统计方案，应根据主要指标、预期差异、重复测量结构、先导结果和招募条件确定。多次观察同一个用户并不等于获得了同样数量的独立被试。材料没有规定可以直接照搬的人数，也没有保证某种方案一定显著。

**投入范围与阶段安排建议**

| 优先级 | 现在应怎样处理 |
| --- | --- |
| 第一阶段优先 | 明确人群和场景、精读直接竞争工作、定一个核心问题、保留用户控制、补研究日志、制定比较方案、做小规模试用 |
| 随问题决定 | 音频与叹气、屏幕上下文、流式多模态、支持效果记忆、轻量动作与语言比较；每项都应说明为检验什么问题所必需 |
| 后续深化 | 跨会话个性化、支持渐退、自主性与持续关系；先选择一个方向 |
| 近期暂缓 | 更多角色和动画、音乐扩展、三维形象、手机端、通用多智能体平台、从零训练大型模型 |

暂缓只是本次规划建议。如果其中某项已经是导师或学校正式要求，需要在对齐时明确调整，不能直接当作取消。特别是叹气检测，原计划的必做定位与新研究主线之间需要单独处理。

建议先用两周完成“范围＋相关工作＋实验草案”的闭环：第一周梳理一页范围说明，优先核对索引中的Epimopilot、GPTalk、Emotional SRLbot，以及与主动介入直接相关的工作；第二周完成核心问题、比较条件、日志字段和一次学习流程样例，提交导师讨论。记忆方向在确定主线后再深入精读，避免所有领域同时推进。

随后约一至三个月稳定实验原型、完成小规模需求与可用性试用；再依据反馈开展第一轮正式机制比较。后续在一至两年的总周期内安排跨会话部署、记忆或自主性研究与论文材料。以上只是相对阶段建议，不是导师给定的截止日期或保证工期。

**需要导师拍板的最少事项**

1. 研究定位更偏人机交互、教育效果，还是多模态／智能体算法？是否存在明确算法创新要求？
2. 第一阶段主要证明什么：介入更合适、学习行为改善，还是长期自主性？主线能否先收敛到需求与可打扰性的区分？
3. 面向谁、学习什么、在什么环境使用？能够招募哪些真实用户、支持多长时间的研究？
4. 现有十二周计划是第一阶段原型，还是独立验收要求？其中叹气、语音和多模态融合哪些仍是硬要求？
5. 第一次可检查成果、第一年成果形式和截止时间是什么？设备、模型调用、参与者补偿及研究审批资源怎样安排？

可直接用于沟通的表述：

> 老师，我把这份索引理解为一至两年的研究方向地图：现有桌宠是实验载体，接下来需要收敛一个学习支持机制，并用真实行为证据验证。我想第一阶段聚焦“区分支持需求与当前可打扰性，并允许用户协商介入”，先完成相关工作对比、可实验原型和一轮用户研究；之后再选择策略效果记忆或支持渐退深化。想和您确认研究定位、目标人群、首阶段成果要求，以及原计划中的叹气检测等是否仍为必做。

最终交付物应能对应一条完整证据链：清楚的问题与相关工作 → 可检查的机制和原型 → 匹配问题的数据与比较实验 → 可复现的结果及边界。即使某个机制没有得到预期效果，也应如实报告；研究完成不以预设的正面结论为条件。
