# 桌面学习陪伴智能体的主动支持策略

导师讨论稿 · 2026年11月19日

**研究问题。** 成年大学生在 Windows 桌面独立完成基础逻辑练习时，把“当前是否需要下一步提示”和“此刻是否方便被询问”分别判断，并在延后时重新评估，能否比状态触发与冷却规则减少不合适的询问，同时保留及时支持？研究也观察答题进展和用户感受到的打扰。

| 项目 | 首阶段范围 |
| --- | --- |
| 对象与任务 | 18 岁及以上在校大学生，在统一的本地练习页面单人作答。每道题有可核验的关键步骤和预写的分级提示。 |
| 支持内容 | 只研究卡在当前步骤时的下一步提示。用户可以主动求助，也可以把主动提示延后或拒绝。 |
| 系统输入 | 首轮统一用步骤进度、尝试、任务停顿和用户明确反馈，摄像头和麦克风均关闭。视觉线索可在后续比较中作为两组共同的输入。 |
| 原型范围 | 复用桌宠、计时和反馈入口，补练习事件、策略切换和候选时机日志，两个条件共用预写提示。 |

**要验证的设计。** 同样是停在一道题上，学生可能正在独立推理，也可能已经卡住，或者虽需要帮助但希望先写完当前一步。把现有状态触发与冷却规则适配到练习页，用同一套卡顿规则为两个条件识别可能的需求。新策略额外判断当前时机，必要时等待，并按用户意愿重新判断。两个条件固定桌宠、信号来源、提示内容和用户控制。正式比较采用随机平衡的被试内交叉设计，每人体验两种策略及难度近似的不同题组。

**怎样判断是否值得继续。** 两个条件都抽查统一时间槽，覆盖询问已出现和未出现的时段。根据用户对“当时是否想要提示”和“是否方便被询问”的回顾，比较每 100 个可评价时间槽中的不匹配次数，并拆看不合适的询问和漏支持。答题进展用正确关键步骤完成率衡量，另记录用户感受到的打扰。首轮结论限于所选任务的介入质量和当下行为。

**与已有研究的关系。** Epimopilot 已用集体困难信号和个人暂停行为共同控制介入。会议研究也提出了兼顾支持需求与当前可打扰性的时机视角。本课题拟检验这类机制在桌面独立练习中的实现及效果，具体差异以比较表和后续精读为准。 [Epimopilot 原文](https://doi.org/10.1145/3772318.3791067) · [Are We On Track? 作者版](https://xinyuechen-flora.github.io/Xinyue___In_meeting_reflection___new%20%2827%29.pdf)

**第一阶段交付。** 冻结范围和两套可比较的策略，提交可运行原型、试用记录、正式实验方案及结果。后续据此选择跨会话的支持效果记忆或支持逐步减少后的自主性研究。

**请导师确认。** 研究是否优先做人机交互中的时机与打扰，是否另有教育效果或算法创新要求。能否用成年大学生和基础逻辑练习作为首轮范围。原计划的叹气检测、语音和多模态融合是否单列验收，以及首个验收节点和可用招募资源。
