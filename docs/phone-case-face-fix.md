# 手机壳假脸修复与验证

本修复只调整检测结果解析、结果关联、提醒判定和诊断显示。YOLO、MediaPipe、预览队列、两路推理线程及其频率不变。

## 判定规则

- 人脸框和该脸的完整 Blendshape 向量逐一配对保留；不会把两张脸的眉部分数平均，也不会借用另一个候选的向量。
- 主用户通过框的交并比、位置和尺寸连续性跟踪，至少连续匹配3次且观察约0.35秒后才可靠。首次同时出现多个候选时，只尝试跟踪明显占主导且不落在手机内的候选；无法可靠选择时暂停提醒。
- 只有主用户可靠、额外候选明显更小、至少85%落在可信手机框内，且至少3个不同手机采集时间戳、跨度至少0.5秒，显示出额外候选与手机共同移动时，才过滤该候选。手机需移动至少图像宽高归一化距离0.02，二者位移差不超过0.015；相对位置也须稳定。
- 曾稳定出现在手机之外的候选不能仅因之后发生重叠而被过滤。单纯静止重叠、低置信度、位置靠近均不足以授权过滤。
- 手机置信度至少0.45，时间戳不得来自未来或倒退，与面部帧相差最多0.35秒，并须满足原有结果时效检查。手机框缺失、过期或未对齐的当前帧不进行过滤。新鲜的手机阴性结果会清除附件证明，避免沿用已失效的判断。
- 原始候选不会删除。灰色虚框表示被排除的手机相关候选；绿色框表示可靠主用户，其余候选保留待确认。

这些是保守的几何启发式，不是身份认证或假脸模型。相机视角、检测框抖动、手机静止不动或遮挡导致证据不足时，会继续按多人保护处理，不保证所有手机壳都能被自动排除。

## 提醒与眉部

| 状态 | 行为 |
| --- | --- |
| 稳定单人 | 使用当前主用户；按原有手机、眉部条件累计 |
| 短暂不确定 | 暂停正向累计，最多保留原有证据1.25秒；恢复的第一个间隔也不计入 |
| 确认多人 | 额外候选连续约1秒仍无法排除时暂停提醒并清空证据；恢复单人需稳定约0.35秒，或额外候选已满足跨度至少0.5秒的更强手机关联证明 |

主用户离开、特征缺失或过期时不使用旧的眉部分数。已证实随手机移动的候选在持续可跟踪期间，即使手机检测随后丢失，也不能被重新选为主用户；当前帧仍不据此过滤人脸或启用提醒。主用户轨迹更换后不继承上一人的累计时间。提醒持续时间、共享冷却、仅专注时提醒、隐藏和用户暂停功能保持原有设置。

眉部校准也只接受当前可靠主用户，不会因为原始候选数仍为2就拒绝已经可靠排除假脸的画面。

## 诊断

沿用应用本地 `momo.log`，由主程序接收状态后写入，避免子进程日志丢失；不保存画面或 Blendshape 向量。限频记录状态变化：

```text
face_state=uncertain reason=phone_candidate_pending candidates=2 filtered=0 primary=1 phone_skew_ms=...
face_state=single reason=phone_attached_filtered candidates=2 filtered=1 primary=1 phone_skew_ms=...
face_state=multiple reason=confirmed_multiple candidates=2 filtered=0 primary=1 phone_skew_ms=...
```

`phone_unaligned` 表示本帧不能关联手机结果；`primary_missing` 表示主用户轨迹没有匹配；`acquiring_primary`、`single_recovery` 分别表示首次确认及多人后的恢复过程。以上计数表示判定状态，不是对真实人数的绝对确认。

## 自动验证

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe main.py --vision-smoke-test --vision-fixtures .artifacts/vision-fixtures --preview-path .artifacts/phone-case-face-smoke.png
```

回归覆盖单人、主用户与随手机移动的假脸、真实两人、静止重叠、独立人脸之后被手机遮盖、低置信度、手机丢失与过期、未来/倒退时间戳、候选顺序交换、主用户离开/返回、主用户特征缺失、校准、有限证据保留、多人清零、用户暂停及原有调度。

合成检测结果用于验证判定和计时规则；模型样例用于验证真实模型输出、异步链路及性能。它们不能代替以下真实摄像头验收：

1. 笔记本前拿起问题手机壳，观察主用户框稳定、额外候选出现及排除；测试手机缓慢移动和静止两种情况。
2. 遮住手机、转动手机、露出摄像头区域，确认未关联时暂停累计、过期结果不参与判断。
3. 第二个真人靠近和远离手机区域，确认持续出现时仍启用多人保护。
4. 主用户移出画面再返回，确认眉部分数不会沿用离开前数据，关怀和校准取当前用户。
5. 在真实光照、摄像头帧率与CPU负载下复测；只看诊断日志即可，不需要默认录制摄像头画面。
