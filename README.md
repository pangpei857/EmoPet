# 雨衣皮卡丘学习桌宠

以用户提供的雨衣皮卡丘插画为角色贴图，透明悬浮，可以用鼠标互动、拖动和缩放，并陪伴学习计时。

## 直接运行

在本项目文件夹双击 **启动桌宠.cmd**。如果已有打包版，启动器会优先运行 `dist/Momo/Momo.exe`。

- 在学习面板输入任务，选15、25、45分钟，或自定义1—120分钟，然后点“开始专注”。
- 点击头部：闭眼享受摸头、飘出爱心；点击肚子：轻轻扭动；点击闪电尾巴：摆尾和星星回应。
- 移动鼠标：睁眼时原画的棕色眼睛平滑看向鼠标，上下左右都可跟随；鼠标移到肚子、脚下或桌宠窗口外也会持续跟随，缩放和拖动后仍然有效。悬停时角色轻轻摇晃回应。
- 按住左键拖动：移动桌宠，接近屏幕边缘会吸附；拖动不会再触发点击。
- 在皮卡丘身上滚动滚轮：以10%调整大小，范围70%—160%；右键和托盘菜单也可选择大小。
- 双击皮卡丘或点击脚下状态条：打开学习面板；气泡右上角可以直接关闭。
- 可以暂停、继续、结束本轮。完成后气泡会提醒休息，并可开始5分钟休息。
- 关闭学习面板会继续计时；右键桌宠和托盘菜单提供互动动作、隐藏／恢复、置顶、缩放和退出；面板内按Ctrl+Q也可退出。
- 启动时先显示桌宠，双击再打开学习面板。单击托盘图标恢复桌宠，双击托盘图标打开面板。
- 右键或面板右上角“桌宠设置”可锁定位置、开关气泡、找回桌宠。锁定后仍可点击互动和滚轮缩放。
- 隐藏后不会被普通提醒自动唤回；隐藏会取消尚未触发的点击反馈。
- 长气泡会折行，最多显示6行，悬停可查看完整内容，阅读期间暂停自动关闭；气泡变高和切换置顶时保持角色脚下的位置。
- 屏幕可用区域改变后会自动检查位置和大小，“找回桌宠”可将其放回主屏幕右下角。
- 今日专注时长、完成轮数、位置、大小、位置锁定、气泡和置顶状态保存在Windows本地应用数据的 `Momo/MomoStudyPet` 目录。

## 动作与反馈

| 动作 | 表现 | 触发方式 |
| --- | --- | --- |
| 待机 | 呼吸、眨眼、耳朵和尾巴轻摆、眼睛跟随鼠标 | 默认或点击“待机” |
| 关心 | 雨衣角色歪头、爱心 | “关心我”、暂停或结束本轮 |
| 提醒 | 轻跳、耳朵摆动、小闹钟 | “提醒我”、学习／休息计时结束 |
| 鼓励 | 闭眼、跳跃、旋转星星 | “为我加油”、开始学习或继续 |

动作会自动回到当前学习或休息状态，休息时闭眼安静陪伴。原始贴图位于 `assets/raincoat-reference.png`，保持原文件不变，由程序在显示时裁掉原图中的棋盘格与枫叶，并为耳朵、尾巴和眼睛添加动画。日常动作使用预设鼓励语；已接入本地视觉检测与DeepSeek文字对话，尚未接入声音交互。

## QQ音乐联动

- 启动桌宠后，会在后台查找QQ音乐的Windows媒体会话。QQ音乐播放时，皮卡丘下方自动展开歌名、歌手和 **上一首／播放暂停／下一首** 按钮。
- 按钮只发给QQ音乐会话；浏览器等其他播放器不会被当作控制目标。不支持的操作会禁用，操作过程中会短暂禁用按钮以防重复提交。
- 暂停后保留音乐条30秒，方便恢复；暂停时间到、停止播放或QQ音乐会话消失时自动收起。启动桌宠时QQ音乐已经暂停，则等待继续播放后再自动展开。
- 右键桌宠或托盘 → **QQ音乐联动**，可开关 **自动显示音乐条**，或点击 **重新检测QQ音乐**。暂停、关闭联动或退出桌宠不会主动暂停QQ音乐。
- 音乐条与桌宠一起拖动和缩放；空间足够时展开收起保持角色位置，靠近屏幕边缘时会自动避让。隐藏桌宠后，切歌不会自动唤回。

需要QQ音乐客户端向Windows公开系统媒体控制会话。读取不到时，可检查客户端系统媒体控制相关设置和版本，再点击重新检测。界面显示的是客户端提供的歌名、歌手及播放状态，不保存听歌记录，不读取QQ账号密钥。收藏、歌词和音量控制暂未接入。

本模块使用PyWinRT调用Windows媒体接口，后台线程负责事件监听与轻量轮询，Qt主线程负责界面。依赖已经包含在打包版内，无需另装Python或插件。开发和打包验证可运行：

```powershell
.\.venv\Scripts\python.exe main.py --music-smoke-test --preview-path .artifacts/qq-music-preview.png
```

此自测读取真实Windows媒体会话但不发送播放命令；没有正在播放的QQ音乐时，预览使用明确标记的界面演示数据。

## DeepSeek学习对话与任务拆解

1. 右键桌宠选择 **和皮卡丘聊聊 · DeepSeek**，或点击学习面板的 **学习对话**。
2. 打开 **模型配置**，默认服务地址为 `https://api.deepseek.com`，默认模型为 `deepseek-flash`，也可选择 `deepseek-v4-pro`。这两个名称按2026年11月11日[DeepSeek官方文档](https://api-docs.deepseek.com/)核对；模型名称可手动修改。
3. 在应用里填写你自己的DeepSeek API Key，点 **保存并测试连接**。测试仅发送一条短消息，不带学习任务和历史；调用由DeepSeek按其[服务规则](https://api-docs.deepseek.com/quick_start/pricing/)计费。
4. 返回 **学习对话** 输入问题，点击发送或按 **Ctrl+Enter**；Enter换行。支持逐步显示回答、停止生成、新建对话和查看本地历史。
5. 默认勾选 **附带当前学习任务和计时状态**，发送时会附带当前任务、计时状态、计划时长与剩余时间；取消勾选后只发送对话文字。摄像头画面、面部关键点与学习记录不会自动发送给模型。
6. 选择 **拆解任务**，或点击 **拆分当前任务** 填入提示，再发送目标。返回的步骤可在 **学习步骤** 中修改名称和分钟数，点 **保存步骤修改** 保留。
7. 选中一步，点 **放到学习面板**。应用只填入任务和时长，由你点击“开始专注”；当前一轮未完成／结束时不会覆盖任务。

完整回答在聊天面板显示，桌宠气泡显示简短回应。默认关闭深度思考，可以在配置中启用。网络请求异步运行；停止或关闭聊天窗口会断开本地请求并保存收到的部分，已产生的用量仍按平台规则计算。断线、超时、密钥错误、余额不足与限流都有提示，不自动重复发送收费请求。

设置保存在 `settings.json`；API Key由Windows DPAPI加密保存在 `deepseek.key`，与服务地址绑定，不写入普通设置、聊天记录或日志。换电脑请重新填写密钥。对话和修改后的步骤保存在同目录的 `chat_history.sqlite3`，重启后保留。

开发自测使用本地模拟接口，不使用真实API Key，也不代表已完成真实DeepSeek账户验证；实际连接需在应用里填写自己的密钥。接口格式参考[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)和[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

## 视觉陪伴

1. 右键桌宠选择 **视觉陪伴 · 摄像头**，或在学习面板点击同名按钮。
2. 选择设备，点击 **开启摄像头**。摄像头默认关闭，开启后才处理画面；“刷新设备”可重新枚举设备。切换设备前先关闭当前摄像头。
3. 默认只有专注计时运行期间才自动提醒。手机框为黄色，手部关键点为青色，面部框为浅绿色；可以开关镜像预览。
4. 手机靠近手部且持续约 **12秒**、主用户可靠且判定为稳定单人时，触发温和的手机提醒。画面中单独出现手机不会直接触发。提醒后至少间隔 **120秒**。
5. 眉部变化持续约 **5秒**时触发关怀。阈值支持 **0.10～0.95**，每次加减 **0.01**，越低越敏感。独自正对摄像头点击 **校准自然表情 · 3秒**，仅保存数值基线并给出推荐阈值；点击 **使用校准推荐值** 才会应用，手动设置始终直接生效。
6. 手机提醒、眉部关怀、是否仅在专注时提醒、持续时间和提醒间隔都可调整并保存。支持 **暂停提醒10分钟**；隐藏桌宠时暂停视觉自动提醒。
7. 关闭视觉窗口会停止识别、释放摄像头并清除预览。应用退出也会停止子进程。

没有摄像头时，可点 **视频测试** 打开本地视频验证模型。视频测试只显示结果，不自动提醒，也不能进行个人表情校准。无设备、占用、断开或超时会显示可重试的提示。

所有推理在本机CPU进行，采集与推理位于独立进程。摄像头持续读取最新画面，预览与检测分别使用有容量限制的队列；面部／手部检测最高约15次/秒，手机检测独立运行、最高约3次/秒，预览目标最高30帧/秒，实际速度取决于设备。模型忙碌时跳过旧帧，不等待手机检测后才刷新画面。不会保存或上传画面，不启用麦克风。

预览下方显示手机置信度、手部关联、眉部分值与实际阈值，以及两类提醒未触发的原因、持续累计和冷却时间。运行信息显示预览帧率、应用内画面传递与面部结果延迟、各模型耗时和检测频率。该延迟从应用读取画面开始计算，不包含摄像头硬件内部延迟。过期检测框会隐藏，过期结果不会用于自动提醒；关闭窗口后同时停止采集与两个检测任务。

手机与手部的空间关系只是“疑似使用”的线索；眉部系数也不能判断人的真实情绪。请保持单人、光线足够，面部、手部和手机尽量进入画面。遮挡、侧脸、远处小手机可能漏检，需要结合实际桌面场景调整。

手机壳摄像头区域若被误检成人脸，仅在主用户稳定、手机框新鲜且时间对齐，并存在持续的共同移动证据时才排除。额外人脸待确认时暂停累计、有限保留已有证据；确认多人时清空并暂停提醒。眉部与校准只使用当前可靠主用户的特征。具体规则、诊断日志及真实摄像头验收步骤见[手机壳假脸修复说明](docs/phone-case-face-fix.md)。

## 回应提醒与学习记录

视觉提醒的气泡提供直接回应：

- **我在查资料**：本轮暂停手机提醒5分钟，保留眉部关怀；提前结束本轮或开始新一轮会恢复手机提醒。
- **这次识别错了**：保存你的误报标记，1分钟内不重复这类提醒。不会直接修改模型或检测阈值。
- **稍后提醒**：暂停全部视觉提醒10分钟，可在视觉陪伴窗口提前恢复。

右键桌宠选择 **发送示例提醒**，或进入 **学习记录 → 发送示例提醒**，即可在没有摄像头、没有开始计时的情况下体验。示例有明确标记，不会启动摄像头、改变真实提醒的暂停状态或计入真实提醒数量。关闭气泡提示后，仍可在记录页回应示例。

学习面板和右键／托盘菜单均提供 **学习记录** 入口：

- **每轮学习**：任务、开始／结束时间、计划时长、实际投入、暂停次数、完成状态与相关提醒。
- **提醒与反馈**：提醒来源、关联任务和你的回应；气泡收起后可补标误报。旧轮次的反馈不会暂停新一轮的提醒。
- 支持今天、近7天、全部记录；汇总中的提醒次数仅表示触发次数，不代表不专注次数。
- 暂停时长不计入实际投入；休息单独保存，不增加学习时长和完成学习轮数。跨午夜的学习时间按日期拆分。
- 开始、暂停、继续、结束和退出时保存记录；进行中约每10秒自动保存。异常退出后，保留到最近一次自动保存并标记“意外中断”。

记录保存为本地应用数据目录中的 `study_history.sqlite3`，设置仍保存在 `settings.json`。只记录任务、时间、提醒类型和用户回应，不保存摄像头画面、面部关键点或音频。升级时一次性保留旧版已有的当日汇总；旧版没有的逐轮明细不会补造。

## 开发运行

使用64位Python 3.12创建环境，安装依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe main.py
```

本次开发环境使用Python 3.12，依赖已安装在项目的 `.venv` 中。视觉运行使用OpenCV、ONNX Runtime和MediaPipe；模型已包含在 `assets/models` 中，无需运行时下载。使用打包版无需另装Python。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe main.py --smoke-test --preview-path .artifacts/mvp-preview.png
.\.venv\Scripts\python.exe main.py --vision-smoke-test --preview-path .artifacts/vision-preview.png
.\.venv\Scripts\python.exe main.py --companion-smoke-test --preview-path .artifacts/learning-history-preview.png
.\.venv\Scripts\python.exe main.py --chat-smoke-test --preview-path .artifacts/deepseek-chat-preview.png
.\.venv\Scripts\python.exe tools/render_assets.py
.\.venv\Scripts\python.exe main.py --profile-dir .artifacts/desktop-qa-profile
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

打包结果为 `dist/Momo/Momo.exe`，分发时应复制整个 `Momo` 文件夹。第三方库的许可文件应随完整文件夹保留。

## 代码入口

- `main.py`：启动、单实例和界面冒烟验证。
- `study_pet/focus.py`：独立的计时逻辑，采用单调时间，避免界面卡顿造成计时漂移。
- `study_pet/ui.py`：桌宠、学习面板、托盘与交互。
- `study_pet/pikachu.py`：角色动作、鼠标分区与手势。
- `study_pet/raincoat.py`：原画贴图、透明轮廓、耳朵与尾巴分层、眼睛纹理跟随。
- `study_pet/storage.py`：本地设置和当日计时摘要。
- `study_pet/music_core.py`：QQ音乐来源匹配、播放状态和暂停后的显示时间。
- `study_pet/music_service.py`：后台Windows媒体会话监听、指定会话控制与退出清理。
- `study_pet/music_ui.py`：跟随桌宠缩放的音乐条及绘制按钮。
- `study_pet/camera_ui.py`：视觉预览、设置、校准与提醒联动。
- `study_pet/camera.py`：独立识别进程的启动、停止、超时处理和设备枚举。
- `study_pet/vision_worker.py`：摄像头／本地视频采集与有界画面队列。
- `study_pet/vision_pipeline.py`：最新帧覆盖、面部／手部与手机独立调度、结果时效保护。
- `study_pet/vision.py`：YOLOv8s ONNX手机检测、MediaPipe面部与手部特征。
- `study_pet/perception.py`：不依赖图像的观察数据、持续证据、冷却和关怀规则。
- `study_pet/history.py`：SQLite学习轮次、提醒回应、旧版汇总迁移与日期统计。
- `study_pet/history_ui.py`：学习记录、提醒列表和反馈入口。
- `study_pet/chat_core.py`：DeepSeek请求参数、有限对话上下文、流式解析和步骤校验。
- `study_pet/chat_network.py`：异步HTTPS请求、停止、超时与错误处理。
- `study_pet/chat_ui.py`：聊天、模型配置与可编辑的学习步骤。
- `study_pet/chat_store.py`：本地对话与计划存储。
- `study_pet/secrets.py`：Windows本机加密密钥存储。

模型来源、哈希与上游许可说明位于 `assets/models/NOTICE.md` 和 `manifest.json`。开发时重新导出模型使用独立环境安装 `torch==2.6.0`（CPU）、`torchvision==0.21.0`、`ultralytics==8.3.162`、`onnx==1.17.0`，再运行 `tools/prepare_vision_models.py --export-phone`；这些导出工具不随运行版打包。

需要使用公开样例检查真实模型时，先运行 `tools/fetch_vision_fixtures.py`，再为视觉冒烟测试添加 `--vision-fixtures .artifacts/vision-fixtures`。测试样例不随应用分发。
