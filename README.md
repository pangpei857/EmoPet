# 雨衣皮卡丘学习桌宠

以用户提供的雨衣皮卡丘插画为角色贴图，透明悬浮，可以用鼠标互动、拖动和缩放，并陪伴学习计时。

## 直接运行

在本项目文件夹双击 **启动桌宠.cmd**。如果已有打包版，启动器会优先运行 `dist/Momo/Momo.exe`。

- 在学习面板输入任务，选15、25、45分钟，或自定义1—120分钟，然后点“开始专注”。
- 点击头部：闭眼享受摸头、飘出爱心；点击肚子：轻轻扭动；点击闪电尾巴：摆尾和星星回应。
- 移动鼠标：睁眼时原画的棕色眼睛平滑看向鼠标，上下左右都可跟随；鼠标移到肚子、脚下或桌宠窗口外也会持续跟随，缩放和拖动后仍然有效。悬停时角色轻轻摇晃回应。
- 按住左键拖动：移动桌宠，接近屏幕边缘会吸附；拖动不会再触发点击。
- 在皮卡丘身上滚动滚轮：以10%调整大小，范围70%—160%；右键和托盘菜单也可选择大小。
- 双击皮卡丘或点击脚下状态条：打开学习面板；气泡右上角可以直接关闭。
- 可以暂停、继续、结束本轮。完成后气泡会提醒休息，并可开始5分钟休息。
- 关闭学习面板会继续计时；右键桌宠和托盘菜单提供互动动作、隐藏／恢复、置顶、缩放和退出；面板内按Ctrl+Q也可退出。
- 启动时先显示桌宠，双击再打开学习面板。单击托盘图标恢复桌宠，双击托盘图标打开面板。
- 右键或面板右上角“桌宠设置”可锁定位置、开关气泡、找回桌宠。锁定后仍可点击互动和滚轮缩放。
- 隐藏后不会被普通提醒自动唤回；隐藏会取消尚未触发的点击反馈。
- 长气泡会折行，最多显示6行，悬停可查看完整内容，阅读期间暂停自动关闭；气泡变高和切换置顶时保持角色脚下的位置。
- 屏幕可用区域改变后会自动检查位置和大小，“找回桌宠”可将其放回主屏幕右下角。
- 今日专注时长、完成轮数、位置、大小、位置锁定、气泡和置顶状态保存在Windows本地应用数据的 `Momo/MomoStudyPet` 目录。

## 动作与反馈

| 动作 | 表现 | 触发方式 |
| --- | --- | --- |
| 待机 | 呼吸、眨眼、耳朵和尾巴轻摆、眼睛跟随鼠标 | 默认或点击“待机” |
| 关心 | 雨衣角色歪头、爱心 | “关心我”、暂停或结束本轮 |
| 提醒 | 轻跳、耳朵摆动、小闹钟 | “提醒我”、学习／休息计时结束 |
| 鼓励 | 闭眼、跳跃、旋转星星 | “为我加油”、开始学习或继续 |

动作会自动回到当前学习或休息状态，休息时闭眼安静陪伴。原始贴图位于 `assets/raincoat-reference.png`，保持原文件不变，由程序在显示时裁掉原图中的棋盘格与枫叶，并为耳朵、尾巴和眼睛添加动画。日常动作使用预设鼓励语。学习对话支持文字和 Windows 本地语音输入与朗读。

## QQ音乐联动

- 启动桌宠后，会在后台查找QQ音乐的Windows媒体会话。QQ音乐播放时，皮卡丘下方自动展开歌名、歌手和 **上一首／播放暂停／下一首** 按钮。
- 按钮只发给QQ音乐会话；浏览器等其他播放器不会被当作控制目标。不支持的操作会禁用，操作过程中会短暂禁用按钮以防重复提交。
- 暂停后保留音乐条30秒，方便恢复；暂停时间到、停止播放或QQ音乐会话消失时自动收起。启动桌宠时QQ音乐已经暂停，则等待继续播放后再自动展开。
- 右键桌宠或托盘 → **QQ音乐联动**，可开关 **自动显示音乐条**，或点击 **重新检测QQ音乐**。暂停、关闭联动或退出桌宠不会主动暂停QQ音乐。
- 音乐条与桌宠一起拖动和缩放；空间足够时展开收起保持角色位置，靠近屏幕边缘时会自动避让。隐藏桌宠后，切歌不会自动唤回。

需要QQ音乐客户端向Windows公开系统媒体控制会话。读取不到时，可检查客户端系统媒体控制相关设置和版本，再点击重新检测。界面显示的是客户端提供的歌名、歌手及播放状态，不保存听歌记录，不读取QQ账号密钥。收藏、歌词和音量控制暂未接入。

本模块使用PyWinRT调用Windows媒体接口，后台线程负责事件监听与轻量轮询，Qt主线程负责界面。依赖已经包含在打包版内，无需另装Python或插件。开发和打包验证可运行：

```powershell
.\.venv\Scripts\python.exe main.py --music-smoke-test --preview-path .artifacts/qq-music-preview.png
```

此自测读取真实Windows媒体会话但不发送播放命令；没有正在播放的QQ音乐时，预览使用明确标记的界面演示数据。

## DeepSeek学习对话与任务拆解

1. 右键桌宠选择 **和皮卡丘聊聊 · DeepSeek**，或点击学习面板的 **学习对话**。
2. 打开 **模型配置**，默认服务地址为 `https://api.deepseek.com`，默认模型为 `deepseek-flash`，也可选择 `deepseek-v4-pro`。这两个名称按2026年11月11日[DeepSeek官方文档](https://api-docs.deepseek.com/)核对；模型名称可手动修改。
3. 在应用里填写你自己的DeepSeek API Key，点 **保存并测试连接**。测试仅发送一条短消息，不带学习任务和历史；调用由DeepSeek按其[服务规则](https://api-docs.deepseek.com/quick_start/pricing/)计费。
4. 返回 **学习对话** 输入问题，点击发送或按 **Ctrl+Enter**；Enter换行。支持逐步显示回答、停止生成、新建对话和查看本地历史。
5. 默认勾选 **附带当前学习任务和计时状态**，发送时会附带当前任务、计时状态、计划时长与剩余时间；取消勾选后只发送对话文字。摄像头画面、面部关键点与学习记录不会自动发送给模型。
6. 选择 **拆解任务**，或点击 **拆分当前任务** 填入提示，再发送目标。返回的步骤可在 **学习步骤** 中修改名称和分钟数，点 **保存步骤修改** 保留。
7. 选中一步，点 **放到学习面板**。应用只填入任务和时长，由你点击“开始专注”；当前一轮未完成／结束时不会覆盖任务。

完整回答在聊天面板显示，桌宠气泡显示简短回应。默认关闭深度思考，可以在配置中启用。网络请求异步运行；停止或关闭聊天窗口会断开本地请求并保存收到的部分，已产生的用量仍按平台规则计算。断线、超时、密钥错误、余额不足与限流都有提示，不自动重复发送收费请求。

设置保存在 `settings.json`；API Key由Windows DPAPI加密保存在 `deepseek.key`，与服务地址绑定，不写入普通设置、聊天记录或日志。换电脑请重新填写密钥。对话和修改后的步骤保存在同目录的 `chat_history.sqlite3`，重启后保留。

开发自测使用本地模拟接口，不使用真实API Key，也不代表已完成真实DeepSeek账户验证；实际连接需在应用里填写自己的密钥。接口格式参考[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)和[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

## 主动关怀与中途休息

- 学习面板提供 **主动关怀** 总开关，以及 **15～120分钟** 的休息提醒间隔，默认60分钟。按实际运行的学习计时跨轮次累计，切任务和短暂停不会清零；这不是摄像头证明的专注时长。应用重启后重新累计，系统休眠或长时间卡顿不补算学习。
- 达到间隔后可直接选 **休息5分钟**、**再学10分钟** 或 **这次先不用**。学习中也能点击休息；原任务、轮次和剩余时间会保留，休息完成后点 **继续原任务**，提前结束休息则原任务保持暂停。完整休息才重置累计。
- 休息、眉部、低头、手机和实验性声音提示经过统一调度。规则先判断是否有支持线索，再判断是否适合开口。视觉陪伴开启时，确认离位或在位不明会暂缓自动提示。摄像头关闭时保留计时提醒。勿扰、对话占用、语音输入、播报、隐藏桌宠和关闭气泡也会暂缓提示。计时照常，未展示的提醒不计作已提醒，过时的视觉或声音线索会重新判断。
- 眉部或声音关怀可以选 **帮我拆解问题**、**想聊一聊** 或 **我在认真思考**。前两个操作打开并填入学习对话，点击发送后才请求模型。思考和稍后等反馈会影响后续提醒。

在学习面板点 **陪伴设置** 切换 **安静陪伴**、**适时关心** 或 **主动支持**。安静模式暂停主动关怀，仍保留学习计时和手动交互。主动支持模式缩短普通关怀的等待间隔，继续遵守勿扰和用户反馈。面板上的 **勿扰 10 分钟** 可临时静音，也可以提前恢复。

## 语音输入与声音关怀

- **学习对话 → 开始语音输入** 会启用 Windows 本机中文听写。说完点击结束，识别出的文字追加到输入框，可修改或丢弃，再由你点击发送。需要系统具备可供桌面应用使用的中文识别引擎，并允许桌面应用使用默认麦克风。
- 可手动点击 **朗读回复**，也可启用 **自动朗读回复** 或在陪伴设置启用 **朗读主动关怀**。朗读使用 Windows 本机语音，中文内容需要可用的中文系统声音。出错时界面会提示，文字功能仍可用。
- **陪伴设置 → 学习中使用麦克风检测叹气候选（实验）** 默认关闭。开启后只在专注计时运行时用本地 YAMNet 分析音频。适时关心模式要求短时间内出现重复候选，主动支持模式可根据单次候选询问。按键语音输入、播报及播报结束后的短暂时间暂停分析。音频原始数据不保存、不上传。声音候选只能作为关怀线索，真实环境中的误报和漏报仍需验证。 [模型说明](assets/models/YAMNET-NOTICE.md)

## 跨轮次陪伴记忆

在 **陪伴设置** 勾选 **在本机记住我的陪伴反馈** 后，助手记录真实学习轮次中明确作出的提醒反馈。同类反馈在近期多个轮次反复表明某类提醒不合适时，同一学习方式下会减少同类提醒。接受休息并让休息计时完整结束时，系统也可以记录这项完成结果。

你可以在设置中查看、停用或清除陪伴记忆。清除操作只删除用于调整陪伴的反馈记忆。可以在学习对话中选择 **本次附带陪伴偏好**，发送前悬停可查看即将提供的摘要。这个选择每次发送后清空，摘要仅包含结构化类别及反馈计数。学习与对话历史按各自设置单独保存。

## 视觉陪伴

1. 右键桌宠选择 **视觉陪伴 · 摄像头**，或在学习面板点击同名按钮。
2. 选择设备和 **识别方案**，点击 **开启摄像头**。摄像头默认关闭，开启后才处理画面；“刷新设备”可重新枚举设备。切换设备或识别方案前先关闭当前摄像头。

设备列在列表里时，仍需等摄像头送出首帧。首帧到了便显示预览，校准和提醒在本地识别模型就绪后可用。开机后读不到首帧时，助手会释放设备并重试同一台摄像头的兼容方式。仍无画面时，请关闭占用摄像头的应用，重新插拔 USB 摄像头，或用系统的“相机”应用检查画面。
3. 默认只有专注计时运行期间才自动提醒。手机框为黄色，手部关键点为青色，面部框为浅绿色；可以开关镜像预览。
4. 手机靠近手部且持续约 **12秒**、主用户可靠且判定为稳定单人时，触发温和的手机提醒。画面中单独出现手机不会直接触发。提醒后至少间隔 **120秒**。
5. 摄像头可以位于侧面。先保持平常学习朝向，点击 **① 校准学习姿态与自然表情**，再做 **② 校准皱眉动作**；动作校准可靠时会应用推荐值，手动阈值仍可单独调整，也可点击 **使用校准推荐值** 恢复推荐设置。移动镜头或明显改变坐姿后请重新校准。个人头部基线、可见侧眉部线索、短窗平滑和触发／恢复双阈值共同参与判断；侧转或质量不足时拒绝判断，不沿用旧值，局部遮挡仍须实拍评估。
6. 手机提醒、眉部关怀、是否仅在专注时提醒、持续时间和提醒间隔都可调整并保存。支持 **暂停提醒10分钟**；隐藏桌宠时暂停视觉自动提醒。
7. 关闭视觉窗口会停止识别、释放摄像头并清除预览。应用退出也会停止子进程。
8. **持续低头关怀** 使用相对于校准姿态的头部角度，支持电脑、纸质阅读／写题和混合学习模式。低头不是分心判断；“我在看书写题”可以标记学习用途并延后提醒。
9. 在位状态结合可靠主用户与原工位关联人体，持续无脸且无人体后才确认离位。侧脸导致人脸丢失、多人、遮挡、断开和缺少可靠人体关联时显示 **无法判断**。这里没有实现身份认证或照片／视频防伪。
10. **记录学习行为摘要** 单独控制落库；暂停提醒仍可记录，关闭记录后不回填关闭期间的数据。保存的是有起止时间的在位、离位、未知、手机、眉部与低头片段，不保存图像或关键点向量。

没有摄像头时，可点 **视频测试** 打开本地视频验证模型。视频测试只显示结果，不自动提醒，也不能进行个人表情校准。无设备、占用、断开或超时会显示可重试的提示。

视觉推理在本机 CPU 进行，采集与推理在独立于桌宠界面的进程中运行。摄像头持续读取最新画面，预览与检测分别使用有容量限制的队列。面部和手部检测最高约15次/秒，人体、手机与可选身体骨架使用另一条最高约3次/秒的推理线程，预览目标最高30帧/秒。模型忙碌时跳过旧帧，预览继续刷新。视觉窗口不保存或上传画面。

预览下方显示手机置信度、手部关联、眉部分值与实际阈值，以及两类提醒未触发的原因、持续累计和冷却时间。运行信息显示预览帧率、应用内画面传递与面部结果延迟、各模型耗时和检测频率。该延迟从应用读取画面开始计算，不包含摄像头硬件内部延迟。过期检测框会隐藏，过期结果不会用于自动提醒；关闭窗口后同时停止采集与两个检测任务。

手机与手部的空间关系只是“疑似使用”的线索；眉部动作不能判断真实情绪。请保持单人、光线足够，面部、手部和手机尽量进入画面。侧置视角需要个人校准，远侧眉眼不可见或手机过小仍可能漏检；现有自动测试不代表实拍识别准确率。

手机壳摄像头区域若被误检成人脸，仅在主用户稳定、手机框新鲜且时间对齐，并存在持续的共同移动证据时才排除。额外人脸待确认时暂停累计、有限保留已有证据；确认多人时清空并暂停提醒。眉部与校准只使用当前可靠主用户的特征。具体规则、诊断日志及真实摄像头验收步骤见[手机壳假脸修复说明](docs/phone-case-face-fix.md)。

### YOLO26s 与身体骨架试用

| 识别方案 | 人体与手机 | 身体骨架 |
| --- | --- | --- |
| YOLOv8s（原版，默认） | YOLOv8s | 预览人体框 |
| YOLO26s + MediaPipe Pose | YOLO26s | MediaPipe Pose Landmarker Lite |
| YOLO26s + RTMPose-s | YOLO26s | RTMPose-s Body7 |

两个试用方案都在检测到单个人体后，用同一帧的人体框估计姿态，预览以紫色绘制身体关键点。面部和手部继续使用 MediaPipe。身体骨架用于预览和对照，视觉提醒和行为日志仍依据面部、手部、手机和人体框线索。切换方案后可使用同一段本地视频比较，选择会随设置保存。

在72张固定抽样的 COCO val2017 图像上，两个 YOLO 模型使用相同输入尺寸、阈值和 CPU 线程数。以 IoU ≥ 0.5 匹配标注框，YOLOv8s 与 YOLO26s 分别检出 112/140 和 117/140 个人体，检出 10/26 和 8/26 部手机。每张图的检测耗时中位数为134和114毫秒。YOLO26s 使用精度优先的推理头，原版保留为默认，方便对照手机漏检。

在其中22张同样由 YOLO26s 定位成功的单人图上，MediaPipe Lite 与 RTMPose-s 分别正确绘制 182/280 和 267/280 个可见标注点。点被绘制且偏差在人体框长边的10%以内时计为正确。单张姿态估计耗时中位数为19和9毫秒。这组数据用于对照模型，工位实拍表现需另测侧置、半身遮挡与小手机场景。

复测时从 [COCO 下载页](https://cocodataset.org/#download) 获取 2017 年的实例和人体关键点标注，将两个 `*_val2017.json` 放在 `.artifacts/vision-coco-val`，再运行下面的命令。样本及结果保存于该目录。

### SemiUHPE 本地头部姿态方案

SemiUHPE 处理头部三维转角，可以独立于身体骨架部署。作者的评估脚本使用 PyTorch、CUDA 与 PyTorch3D。本机设备列表显示 Intel UHD 770 核显，因此先在独立 Python 环境适配 CPU 推理，用 `DAD-WildHead-EffNetV2-S-best.pth` 验证裁剪头部后的输出。[研究代码](https://github.com/hnuzhy/SemiUHPE) · [作者的权重](https://huggingface.co/HoyerChou/SemiUHPE)

适配时保持头部裁剪的长宽比，用推理网络输出的九个数构造矩阵，在 CPU 上投影为有效旋转矩阵，然后计算俯仰、偏航和滚转。接入前，用同一批正面、侧脸和低头片段比较 SemiUHPE 与 MediaPipe 的角度误差、可用率及延迟，核对俯仰方向和个人基线。宽角度需要可靠的头部区域。验证后再评估 ONNX 导出和后台低频运行，将转角作为低头检测的候选输入。眉部关怀仍使用面部特征。SemiUHPE 处于方案阶段。[旋转恢复实现](https://github.com/hnuzhy/SemiUHPE/blob/main/src/fisher/fisher_utils.py)

## 回应提醒与学习记录

视觉提醒的气泡提供直接回应：

- **我在查资料**：本轮暂停手机提醒5分钟，保留眉部关怀；提前结束本轮或开始新一轮会恢复手机提醒。
- **这次识别错了**：保存你的误报标记，1分钟内不重复这类提醒。不会直接修改模型或检测阈值。
- **稍后提醒**：暂停全部视觉提醒10分钟，可在视觉陪伴窗口提前恢复。

右键桌宠选择 **发送示例提醒**，或进入 **学习记录 → 发送示例提醒**，即可在没有摄像头、没有开始计时的情况下体验。示例有明确标记，不会启动摄像头、改变真实提醒的暂停状态或计入真实提醒数量。关闭气泡提示后，仍可在记录页回应示例。

学习面板和右键／托盘菜单均提供 **学习记录** 入口：

- **每轮学习**：任务、开始／结束时间、计划时长、实际投入、暂停次数、完成状态与相关提醒。
- **提醒与反馈**：提醒来源、关联任务和你的回应；气泡收起后可补标误报。旧轮次的反馈不会暂停新一轮的提醒。
- 支持今天、近7天、全部记录；汇总中的提醒次数仅表示触发次数，不代表不专注次数。
- **行为时间线**：每段行为单独记录，重复提醒不增加行为次数；可以补标误报、查资料、正在思考或看书写题。
- **学习小结**：每轮结束自动保存本地统计版，显示计时、有效视觉覆盖、在位／离位／未知与未观测、行为片段、关联问答及用户补充；也可按日期查看当天汇总。
- 每条问答按发送时所属轮次保存，聊天窗口跨轮或跨日不会把整个对话错误归到同一轮。旧版问答没有可靠轮次归属时保持未关联。
- 在小结页勾选发送选中范围的文字和统计，再点 **使用DeepSeek生成** 才会联网生成讨论点与建议；不发送画面。断网、空返回或校验失败时保留本地版；事件纠正后旧复盘标记过期，重新生成时使用新事实。
- 暂停时长不计入实际投入；休息单独保存，不增加学习时长和完成学习轮数。跨午夜的学习时间按日期拆分。
- 开始、暂停、继续、结束和退出时保存记录；进行中约每10秒自动保存。异常退出后，保留到最近一次自动保存并标记“意外中断”。

记录保存为本地应用数据目录中的 `study_history.sqlite3`，设置仍保存在 `settings.json`。学习任务、行为摘要、提醒反馈和小结在本地保存；对话仍在 `chat_history.sqlite3`。不保存摄像头画面、面部关键点或音频。升级保留旧数据，不补造旧版缺少的行为、问答归属或轮次明细。更完整的使用与验证说明见[主动陪伴与侧置摄像头](docs/主动陪伴与侧置摄像头.md)。
